# Admin audit — 11 November 2026

## Scope and evidence

Reviewed admin routes, navigation, customer aggregation, report loading, authentication, support replies and the Santa report API. Inspected live Overview, Customers, Support Tickets, Santa Call Analytics, Christmas Analytics and the broken Publisher navigation in the authenticated Chrome session. Read-only server probes checked actual table/column availability. No customer messages, campaigns, refunds, real payments or production data edits were performed.

This is not a claim that every content-generation, publishing, pricing mutation or delivery integration passed an end-to-end production test.

## Corrections in this branch

- Operations home prioritizes support, customers, fulfillment and the dedicated Santa funnel. Secondary content/email/pricing tools are behind a disclosure. Historical credit reporting remains accessible and is explicitly scoped.
- Publisher, Factory RAW, Content Autopilot and Music Library now have their missing routes; Publisher live previously redirected to the homepage.
- Campaigns was byte-for-byte identical to Offers and wrote to the same `email_offers` table. Removed duplicate implementation/navigation; old campaign URLs redirect to Offers. No campaign sending service was found or invented.
- Empty Studio page links to existing production tools instead of promising nonexistent functionality.
- Customers includes registered accounts and guest orders from Christmas, Pet and credits. Email normalization merges sources; paid totals are separated by currency; unconfirmed orders are not called purchases. Identifiable test/noncommercial checkouts are excluded. Missing sources are explicit and disable CSV export. Spreadsheet formula cells are escaped.
- Paginated, bounded reads detect server row caps, missing counts and changing datasets. Christmas reports and orders no longer silently stop at a local 200-row or server default boundary. Reporting errors hide totals; auxiliary source errors are visible. Legacy overview no longer substitutes all-time counts for an empty date range or merges unknown/non-EUR revenue as EUR.
- Admin route, helper and Santa endpoint use the existing `is_admin` database authority; access verification failures show a retry instead of silently redirecting as non-admin. RLS and grants are unchanged.
- Support has polling fallback, per-ticket unsent drafts, duplicate-send guard, captured mutation ticket IDs and late-response isolation. Failed loads are explicit. Replies are labeled as in-chat, not emailed. Closing changes ticket status without first inserting a misleading closing message. Failed or stale queued email alerts are surfaced.
- Restored `admin_dashboard` action in the local Santa backend (live already has this action). Reporting remains available during the call kill switch. Local report reads do not require refund columns absent from repository migrations. Refund count is explicitly unavailable until Santa refund reconciliation is verified.
- Browser purchase analytics no longer substitute the advertised price when server confirmation omits the actual amount.

6. Santa refund ingestion/reconciliation is not verified. Consult Stripe for refunds; the new admin report deliberately does not claim a verified zero.

Frontend-only deployment does not activate the missing support notification schema/worker or analytics credentials.
